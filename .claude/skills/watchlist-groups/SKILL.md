# Watchlist Groups

판정은 스크립트가 한다. 이 스킬은 호출하고, 결과를 읽어 설명한다. 규칙 숫자를 눈으로 다시 계산하거나
고치지 않는다 — 규칙은 `scripts/watchlist/classify.mjs`, 근거는 `docs/watchlist-rules.md` 에 있다.

## 호출

```bash
node scripts/watchlist.mjs check --name 현대해상
node scripts/watchlist.mjs check --symbol 001450 [--as-of YYYYMMDD]
```

- 여러 종목은 종목마다 한 번씩 부른다(종목당 약 1.5초, 종목 목록은 하루 한 번만 받는다).
  관심종목 전체 점검을 요청받으면 `.claude/investments/watchlist.yaml` 의 종목을 차례로 부르되,
  사용자가 명시적으로 요청하지 않는 한 그 파일에 결과를 쓰지 않는다.
- 장중에 부르면 오늘 봉은 미완성이라 전일 마감 기준으로 판정한다. 결과의 `asOf` 를 사용자에게 밝힌다.
- 이름이 여러 종목에 맞으면 스크립트가 후보를 담아 실패한다. 추측하지 말고 사용자에게 어느 종목인지 묻는다.
- 종료 코드: 2 사용법, 3 인증, 4 브로커·네트워크, 5 호출 한도. 오류 JSON 은 stderr 에 나온다.

## 결과 읽기

| `action` | `status` | 사용자에게 전할 것 |
|---|---|---|
| `alert` | `setup` | 3그룹. `orders.alert` 에 알림, `orders.buyStop`(피봇)에 매수 스톱, `orders.stopLoss`, 추격 한도 `orders.chaseLimit` |
| `watch` | `breaking_out` | 이미 피봇 위(추격 한도 안). 백테스트는 피봇 아래에서 잡은 셋업만 검증했다는 점을 함께 말한다 |
| `watch` | `extended` | 피봇 +5% 초과 — 추격하지 않는다. 다음 베이스를 기다린다 |
| `watch` | `far_below_pivot` | 3그룹 모양이지만 피봇에서 멀다. 가까워지면 다시 확인 |
| `watch` | `g3_candidate` | 2그룹이고 `g2Score` 가 높다 — 3그룹 후보로 자주 확인 |
| `watch` | `g2` | 2그룹. 수축(변동성 축소)을 기다린다 |
| `exclude` | `overheated` | 1그룹(과열). 좋아 보여도 사지 않는다 — 이 자리 돌파는 우위가 없었다 |
| `exclude` | `no_group` | 어느 그룹도 아님. `checks` 에서 떨어진 조건(`pass: false`)을 근거로 든다 |
| `exclude` | `illiquid` / `insufficient_history` | 거래대금이 얇거나 일봉이 모자라 판정 대상 밖 |

- `groups` 는 겹칠 수 있다(2·3그룹 동시). 행동은 `action` 하나만 따른다.
- `strength.rel` 은 종목 강도 ÷ 자기 시장 지수(코스피 0001 / 코스닥 1001) 강도다. 1 미만이면 지수보다 약하다.
  수축 모양이 좋아도 지수보다 약하면 제외된다 — 그렇게 설명한다.
- `checks` 의 값을 인용할 때는 규칙 이름(`rule`)과 실제 값(`value`)을 같이 쓴다.

## 알림이 울린 날 (스크립트가 볼 수 없는 것)

`alert` 종목의 알림이 울리면 매수 전에 사용자에게 두 가지를 확인하게 한다.

1. 그 종목 거래량이 평소(50일 평균)보다 확실히 많은가 — 1.5배 이상이면 성과가 더 좋았다.
2. 같은 업종이 함께 오르는가 — 같은 업종에서 +3% 넘게 오른 종목이 드문 날의 돌파는 성과가 없었다.

알림가에서 미리 사지 않는다. 매수는 피봇을 넘을 때(매수 스톱)이고, 손절은 매수와 동시에 건다.
